# 아이디어 도출 화면 재설계 구현 지시서

## 목표

현재 `아이디어 도출` 탭을 **주제 설계 ↔ 핵심아이디어 ↔ 성취기준**이 한 페이지에서 함께 변하는 작업 공간으로 재설계한다. 교사는 어느 영역에서든 시작하고, 다른 영역의 추천을 확인한 뒤 직접 수정·추가·삭제할 수 있어야 한다. `수업 조건 → 성취기준 탐색 → 주제 후보 비교`처럼 단계를 밟는 화면과 후보 3개를 생성해야 다음 작업을 할 수 있는 구조는 제거한다.

이 문서는 실제 구현 지시서다. 설명용 시안만 만들지 말고 현재 앱의 아이디어 도출 탭에 연결한다. 이 작업 범위에 속하지 않는 수업 설계 카드와 팀 채팅 기능은 유지한다.

## 현재 코드와 데이터 연결 지점

- `src/components/workspace/WorkspaceShell.tsx`가 헤더의 `아이디어 도출` 탭, `IdeationWorkspace`의 props, 오른쪽 채팅 패널의 열기/접기를 관리한다. 아이디어 도출에서 채팅은 기본 접힘 상태로 유지하고, 사용자가 원할 때만 열 수 있게 한다.
- `src/components/ideation/IdeationWorkspace.tsx`는 현재 조건 입력, 성취기준 검색, 후보 생성, 후보 비교, 반영 미리보기를 제공한다. 새 화면의 중심 구현 지점이다. 상단의 영문 장식 제목, 단계 버튼, 불필요한 안내 문단과 상시 노출되는 조건 폼은 제거한다.
- `src/lib/ideation/model.ts`, `src/app/api/ideation/route.ts`, `src/app/api/ideation/save/route.ts`, `src/lib/ideation/application.ts`는 현재 `seedIds → 후보 3개`를 전제로 한다. 새 상호 추천과 저장 구조에 맞게 계약을 수정한다. 기존에 저장된 `__ideation` 초안은 읽을 수 있게 마이그레이션하거나 안전하게 변환한다.
- 공식 핵심아이디어 목록은 기존 `IdeasModal`이 읽는 `/standard/ideas.json`을 활용한다. 공식 성취기준 목록은 기존 `/api/standards`와 성취기준 데이터의 코드·교과·영역·원문을 활용한다. 기존 검색 UI의 동작과 데이터 출처를 재사용하되, 아이디어 도출 화면 안에서 선택 결과를 볼 수 있게 한다.
- 수업 설계 카드의 `A-2.final_topic`, `A-3.core_ideas`, `A-3.achievement_standards`, `A-4.integration_narrative`, 전역 선택 항목 `__selected_standards`와의 반영 관계를 확인한다. 아이디어 도출의 임시 저장과 수업 설계 카드 반영은 구분한다. 반영 시 기존 카드의 다른 필드를 지우거나 교사의 기존 입력을 묵시적으로 덮어쓰지 않는다.

## 화면 구조

데스크톱에서는 한 화면에 다음 세 영역을 왼쪽부터 나란히 둔다. 좁은 화면에서는 세 영역을 세로로 쌓는다. 페이지 전체에 세 영역이 항상 존재해야 하며, 탭이나 `다음` 버튼으로 영역을 바꾸지 않는다.

| 영역 | 항상 보이는 내용 | 주요 조작 |
| --- | --- | --- |
| 주제 설계 | 주제 제목, 주제를 구성하는 하위요소 목록 | 주제·하위요소 작성/수정/삭제, 하위요소 추가 |
| 핵심아이디어 | 선택한 공식 핵심아이디어와 직접 작성한 아이디어, 연결된 하위요소 | 검색·선정, 수정/삭제, 양방향 `with AI` |
| 성취기준 | 선택한 성취기준의 교과·코드·원문, 연결된 핵심아이디어 | 검색·선정, 연결 수정/삭제, 양방향 `with AI` |

상단은 `아이디어 도출` 제목, 저장 상태, `진행 저장`, `수업 설계에 반영`만 간결하게 둔다. 수업 조건 중 추천에 꼭 필요한 교과·학년 정보는 작은 `조건` 버튼으로 열어 수정한다. `수업 기본정보를 가져왔습니다. 여기서 조정한 조건은 아이디어 탐색에 사용합니다.`, `중학교 1~3학년 성취기준을 사용합니다. 실제 진도와 이수 여부는 교사가 확인합니다.` 문구는 화면에서 삭제한다. 같은 역할의 장황한 안내 문구를 새로 만들지 않는다.

세 영역 사이의 관계는 **연결된 카드와 선택 상태**로 시각화한다. 하위요소를 선택하면 연결된 핵심아이디어가 강조되고, 핵심아이디어를 선택하면 관련 하위요소와 성취기준이 강조된다. 성취기준을 선택해도 역방향으로 강조된다. 각 카드에서 연결 대상을 짧은 칩으로 볼 수 있고 클릭하면 해당 항목으로 이동하거나 강조한다. 복잡한 전체 그래프는 필수 요소가 아니며, 연결선 때문에 원문과 편집 버튼이 가려지면 카드 중심 UI를 우선한다. 연결이 없는 항목도 표시하고 연결 대상을 찾을 수 있게 한다.

## 주제 설계

- 주제 제목은 사용자가 자유롭게 작성하고 언제든 수정한다.
- 하위요소는 독립된 행으로 추가·수정·삭제한다. 한 주제에 여러 하위요소를 둘 수 있다. 예: 주제 `우리 동네 폭염에 어떻게 대응할까?`, 하위요소 `폭염의 원인`, `취약한 사람과 공간`, `지역의 대응 방안`.
- 하위요소는 핵심아이디어와 many-to-many로 연결한다. 하위요소 문장을 바꿔도 연결을 자동 삭제하지 않는다. 변경된 문장과 기존 연결을 함께 보여주고 필요하면 다시 추천받게 한다.
- 빈 주제나 빈 하위요소에서도 공식 핵심아이디어를 먼저 골라 작업을 시작할 수 있어야 한다.

## 핵심아이디어: 하위요소와 양방향 추천

핵심아이디어 영역에는 선택한 아이디어의 교과·영역·원문과 편집 상태를 표시한다. 공식 데이터에서 고른 항목은 원문과 출처를 유지하고, 교사가 수정한 문장은 별도 수정본으로 보관하여 공식 원문인 것처럼 표시하지 않는다. 직접 작성한 항목도 허용한다.

`with AI`를 누르면 추천 결과를 **이 페이지 안의 사이드 패널 또는 해당 영역의 펼침 패널**에서 보여준다. 채팅 창으로 이동시키지 않는다. 버튼은 현재 선택한 항목과 추천 방향이 분명해야 한다.

1. **하위요소 → 핵심아이디어:** 선택한 하위요소와 현재 교과 조건을 입력으로, 관련 공식 핵심아이디어를 추천한다. 각 제안에 `교과 · 영역 · 원문`, 관련 이유, 연결될 하위요소를 표시한다.
2. **핵심아이디어 → 하위요소:** 선택한 핵심아이디어와 현재 주제를 입력으로, 주제에 추가하거나 기존 문장을 수정할 하위요소를 제안한다. 새 하위요소인지 수정 제안인지 구분한다.

추천 결과는 개별적으로 `추가`, `연결`, `문장에 반영`, `무시`할 수 있게 한다. 여러 제안을 한꺼번에 채택할 수 있어도 각 항목의 내용을 먼저 확인할 수 있어야 한다. 제안은 사용자가 채택하기 전에는 현재 작업 내용을 바꾸지 않는다. 채택 후에도 모든 항목과 연결은 사용자가 수정·삭제할 수 있다.

## 성취기준: 핵심아이디어와 양방향 추천

- 핵심아이디어 → 성취기준: 선택한 핵심아이디어를 기준으로 관련 성취기준을 추천한다. 성취기준의 `교과 · 코드 · 원문`과 연결 이유를 보여준다.
- 성취기준 → 핵심아이디어: 선택한 성취기준을 기준으로 관련 공식 핵심아이디어를 추천한다. 기존에 선택된 핵심아이디어와의 연결 제안, 새 핵심아이디어 추가 제안을 구분한다.
- 사용자는 AI 추천 없이도 성취기준을 코드·교과·영역·본문으로 검색하여 추가하고, 어떤 핵심아이디어와 연결할지 직접 지정할 수 있다.
- 선택된 성취기준은 원문이 읽히는 카드로 표시한다. 연결된 핵심아이디어를 칩으로 보여주며, 연결만 제거하거나 성취기준 자체를 삭제하는 조작을 구분한다.
- 성취기준 원문과 코드는 공식 데이터 그대로 보존한다. 교사의 재진술이나 메모가 필요하면 별도 필드에 저장한다. AI가 공식 성취기준 코드나 원문을 만들어내지 못하게 하고, 추천 결과의 ID를 실제 데이터와 대조한다.

## 공통 상호작용 규칙

- 네 추천 방향은 모두 페이지 내 각 영역의 `with AI` 버튼에서 실행한다. 버튼 주변의 선택 항목과 추천 방향을 드러낸다. 선택 항목이 없으면 먼저 고를 대상을 간단히 안내한다.
- 추천을 다시 실행해도 사용자가 직접 작성하거나 채택한 항목을 자동 삭제·교체하지 않는다. 다른 쪽 항목을 수정했을 때 기존 연결은 남겨 두고 `다시 검토할 연결`처럼 표시해 재추천과 수동 편집을 가능하게 한다.
- 관계는 `하위요소 ↔ 핵심아이디어`, `핵심아이디어 ↔ 성취기준` 두 종류로 저장한다. 한 항목이 여러 항목에 연결될 수 있다. 삭제한 항목에 달린 연결은 함께 정리하고, 연결만 삭제할 때는 양쪽 항목을 유지한다.
- `공식 데이터`, `교사 작성/수정`, `AI 추천`의 출처를 구분한다. AI가 제시한 관련 이유는 해석·제안으로 표시하고 교육과정의 공식 관계인 것처럼 표시하지 않는다.
- 추천 중 로딩·취소·실패·결과 없음 상태를 해당 영역에서 처리한다. 실패해도 현재 입력과 선택은 보존한다.
- 수정과 저장 상태를 분명히 표시한다. 다른 창의 변경과 충돌하면 기존 저장 흐름처럼 사용자 입력을 유지하고 선택 가능한 해결 방법을 제공한다. 수업 소유자가 아닌 참여자는 읽기 권한과 기존 앱의 편집 권한 정책을 따른다.

## 저장 및 수업 설계 반영

`__ideation`에는 주제 제목, 안정적인 ID가 있는 하위요소·핵심아이디어·성취기준, 두 종류의 연결, 항목별 출처와 원문 참조, 교사 수정본, 추천 검토 상태, 데이터 버전을 저장한다. 배열 위치나 화면 순서를 연결 ID로 사용하지 않는다. 저장된 초안을 다시 열었을 때 세 영역의 항목과 연결 상태가 복원되어야 한다.

`수업 설계에 반영`을 누르면 변경 미리보기를 먼저 보여준다. 주제는 `A-2.final_topic`, 선정한 핵심아이디어와 성취기준은 `A-3`의 해당 행, 선택 성취기준은 `__selected_standards`, 확정한 연결 설명은 필요한 경우 `A-4.integration_narrative`에 반영한다. 기존 카드 내용과 새 내용을 비교해서 중복을 피하고, 아이디어 도출 화면에서 삭제했다는 이유만으로 기존 수업 설계 카드의 항목을 자동 삭제하지 않는다. 최종 반영은 현재 앱의 소유자 권한, 충돌 감지, 미리보기 확인 절차를 유지한다.

## 완료 기준

1. 사용자가 주제 제목과 하위요소를 작성하고, 같은 화면에서 핵심아이디어와 성취기준을 검색·선정·수정·삭제할 수 있다.
2. `하위요소 → 핵심아이디어`, `핵심아이디어 → 하위요소`, `핵심아이디어 → 성취기준`, `성취기준 → 핵심아이디어` 네 방향의 `with AI` 추천을 페이지 안에서 확인하고 항목별로 채택하거나 무시할 수 있다.
3. 어느 영역을 수정해도 나머지 영역으로 돌아가 연결을 재검토할 수 있다. 연결 강조와 연결 칩이 양방향으로 일치한다.
4. 페이지 진입이나 작업 과정에 단계 전환이 필요 없고, 채팅은 기본적으로 접혀 있다. 세 영역과 핵심 작업 버튼이 첫 화면에서 확인된다.
5. 저장 후 다시 열어도 항목·연결·교사의 수정 내용이 유지된다. 수업 설계 반영 미리보기에서 기존 카드 내용을 보존하는 결과를 확인할 수 있다.
6. 공식 원문과 AI의 추천·교사의 수정이 구분된다. 모든 수학 용어는 영어로 표현한다.
